# Одна проверка звука на Windows

1. Распаковать архив целиком. Полностью завершить Яндекс Музыку и PulseSync
   (в том числе через значки в трее, не просто свернуть окна). Из папки архива
   выполнить `node install-audio-diagnostics.mjs`. Node.js уже установлен для сборки;
   Yarn, npm install и node_modules не нужны. Установщик обновляет только два
   локальных web-addon, сохраняет их настройки и делает резервную копию в
   `PulseSync/addons/.pulsecolor-audio-backups/`. Магазинные аддоны он не заменяет.
   Затем запустить PulseSync и Яндекс Музыку; тема PulseColor должна быть выбрана.
   При работе с исходниками вместо архива можно использовать обычную сборку/синхронизацию.
2. Включить трек, открыть волну и оставить окно видимым. В DevTools → Console
   выбрать `top`, вставить весь файл `diagnose-audio.js` и нажать Enter.
3. Подождать 12 секунд, скопировать строку `PULSECOLOR_AUDIO_REPORT …` целиком.
   Не ставить паузу и не переключать страницы во время записи.

Никаких дополнительных контекстов выбирать не нужно. Отчёт содержит счётчики
подписки/кадров, состояние SDK-анализатора, уровни сигнала и состояние отрисовки.
Он не запрашивает аккаунт, токены, названия треков, микрофон или системный звук.
`undefined` сразу после вставки — нормальное значение выполнения; нужен итоговый
отчёт через 12 секунд. Если DevTools вместо строки показывает Promise, дождаться
строки с указанным префиксом.

`findings` — диагностические признаки, а не автоматическое доказательство причины.
Отсутствие маркера означает, что компонент не запущен или загружена старая сборка;
подписка без кадров отличается от недоступного SDK и от реально нулевого спектра.

Служебные DOM-маркеры обновляются раз в секунду; полный аудиоспектр в DOM не
копируется. После выключения аддонов их таймеры и маркеры удаляются.
